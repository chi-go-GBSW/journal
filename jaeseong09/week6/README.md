2026.10.21.

## 일주일 동안 만들어낸 것

### 완료한 작업

1. **라운드 생성 및 참여 화면 구현**
   - 게임 시작 시 새 게임 생성과 기존 게임 참여 방식을 선택하는 화면 연결
   - 구장을 검색하고 코스를 선택할 수 있는 화면 구현
   - 20개 파크골프장의 구장·코스·홀 정보를 화면 확인용 데이터로 구성
   - 선택한 구장과 코스 정보를 참가자 화면으로 전달하는 흐름 구성

2. **참가자 초대 기능 구현**
   - 참가자 목록 화면과 초대용 바텀 시트 구현
   - 6자리 초대 코드를 생성하고 QR코드로 표시하는 기능 추가
   - 참여 코드 직접 입력 및 QR코드 스캔 화면 구현

3. **기록 및 설정 화면 추가**
   - 개인 기록과 단체 기록을 구분해 확인할 수 있는 기록 화면 구현
   - 메인 화면에서 기록 및 설정 화면으로 이동하도록 라우팅 연결
   - 설정 기능을 추가할 수 있도록 기본 화면 구조 구성

4. **스크린골프 결과 등록 흐름 구현**
   - 카메라 촬영과 갤러리 선택을 위한 화면 흐름 구성
   - 촬영한 이미지를 확인하고 다시 촬영할 수 있는 화면 구현
   - 결과 분석 화면의 기본 구조 추가

5. **앱 설정 및 패키지 정리**
   - 앱 표시 이름과 아이콘 변경
   - 카메라, 이미지 선택, QR코드 생성 및 암호학적 난수 생성을 위한 패키지 추가
   - 새로 만든 화면들을 Expo Router에 등록

## 일주일 동안 겪었던 힘든 점 및 해결 방법

### 어려웠던 점

1. **여러 화면 사이의 흐름 연결**
   - 라운드 방식 선택부터 구장·코스 선택, 참가자 초대까지 화면 수가 늘어나면서 이동 경로와 전달 데이터를 함께 관리해야 했음

2. **QR코드와 카메라 기능 적용**
   - QR코드 생성·스캔과 사진 촬영 기능은 일반 화면과 달리 카메라 권한 및 기기 기능을 고려해야 했음

3. **화면 구현과 실제 기능 연동의 차이**
   - 기록, 구장 정보 및 참가자 데이터가 아직 임시 데이터에 의존하고 있어 실제 서버 데이터와 연결하지 못함
   - 일부 버튼과 분석·설정 화면은 기본 구조만 있고 실제 동작은 남아 있음

### 해결 방법

1. **기능별 화면과 경로 분리**
   - 라운드 생성, 참여, 참가자 관리, 기록, 설정 및 스크린골프 등록을 각각 별도 화면으로 나누어 구현함
   - Expo Router의 경로와 파라미터를 이용해 화면 간 이동 흐름을 구성함

2. **전용 라이브러리 활용**
   - Expo Camera와 Image Picker를 사용해 QR 스캔 및 이미지 선택 흐름을 구성함
   - Expo Crypto와 QRCode 라이브러리를 이용해 6자리 초대 코드와 QR코드를 생성함

3. **임시 데이터를 이용한 화면 선구현**
   - 백엔드 연동 전에 구장·기록·참가자 예시 데이터를 사용해 전체 화면과 사용자 흐름을 먼저 확인할 수 있도록 함

## 내가 잘한 것과 아쉬웠던 점

### 잘한 점

- 기획 변경으로 추가된 구장 선택과 QR코드 초대 기능을 실제 화면 흐름으로 구체화함
- 라운드 생성부터 참가자 초대까지 여러 화면을 연결해 전체 사용 흐름을 확인할 수 있게 함
- 카메라, 이미지 선택 및 QR코드 관련 라이브러리를 조사하고 프로젝트에 적용함
- TypeScript 검사를 통과하도록 타입을 관리함

### 아쉬웠던 점

- 게임 시작과 참여 확인 등 일부 핵심 버튼이 아직 실제 기능과 연결되지 않음
- 갤러리 선택, 사진 분석 및 설정 화면이 완성되지 않음
- 구장·기록·참가자 정보가 임시 데이터이며 백엔드 API와 연동되지 않음
- 린트 검사에서 사용하지 않는 코드와 불필요한 표현식 관련 경고가 남아 있음

### 시도한 것

- 라운드 생성부터 구장 선택, 참가자 초대, 기록 조회 및 스크린골프 결과 등록까지 주요 프론트 화면을 한 번에 연결하려고 함
- QR코드와 카메라 기능을 적용해 실제 앱과 유사한 사용 흐름을 만들고자 함

### 실패한 것과 그 원인 분석

- 예상했던 결과는 구현한 모든 화면에서 버튼과 데이터가 자연스럽게 이어지는 것이었음
- 실제로는 일부 버튼이 동작과 연결되지 않았고, 기록·구장·참가자 정보도 임시 데이터에 머물렀음
- 한 번에 여러 화면과 기기 기능을 구현하면서 각 기능의 마무리와 검증에 충분한 시간을 사용하지 못함
- 백엔드 API와 사진 분석 기능의 인터페이스가 확정되지 않아 프론트 화면을 먼저 구현한 뒤 연동을 남겨두게 됨

### 해결을 위해 시도한 것

- 기능별로 화면과 라우트를 분리해 전체 흐름을 먼저 확인할 수 있도록 함
- 임시 데이터와 기본 화면을 사용해 서버 연동 전에도 UI를 테스트할 수 있게 함
- TypeScript 및 ESLint 검사를 실행해 현재 남아 있는 타입 문제와 코드 경고를 확인함

### 배운 점 및 추후 계획

- 화면 수를 빠르게 늘리는 것뿐 아니라 각 버튼의 동작과 데이터 전달까지 작은 단위로 완성하고 검증하는 과정이 중요하다는 점을 배움
- 다음 작업에서는 미완성 기능을 먼저 연결하고, 서버 API 구조에 맞춰 임시 데이터를 실제 데이터로 교체할 예정임
