## 일주일 동안 내가 만들어 낸 것

지난 일지 작성 이후 AI 개발 계획과 모델 선정 기준을 정리하고, 실제 서비스에서 사용할 STT/TTS 음성 처리 파이프라인을 구현했다. `faster-whisper` 기반의 한국어 STT와 Edge TTS 기반의 음성 합성 기능을 FastAPI로 연결했으며, 음성 파일 형식과 크기 검사, 예외 처리, 추론 시간과 RTF 등의 성능 지표도 추가했다.

STT 인식률을 높이기 위한 오디오 전처리 기능도 개발했다. 다양한 입력 음성을 16kHz mono WAV로 변환하고, 앞뒤 무음 제거, 노이즈 감소, 음량 정규화를 적용하도록 구현했다. 입력 및 출력 음량, 제거한 무음 길이, 노이즈 감소량, 처리 시간 등의 지표를 함께 기록하도록 구성했다.

또한 AI Hub 경상도 방언 데이터를 이용해 `Whisper large-v3-turbo`를 파인튜닝하기 위한 학습 환경을 구축하고 있다. 데이터 구조 검사, 학습용 manifest 생성, 동일 화자와 동일 대화 세션의 데이터 누수 방지, 음성 길이·클리핑·중복 여부 등의 품질 검사 기능을 작성했다. LoRA와 DoRA를 동일한 조건에서 비교할 수 있도록 학습 설정을 분리하고, 학습 과정과 결과를 WandB에 기록할 수 있도록 구성했다. 문자 오류율뿐 아니라 타수 숫자, OB, 벌타, 취소, 홀 이동 명령처럼 서비스에 중요한 표현의 인식 정확도를 평가하는 기준도 구현했다.

## 일주일 동안 겪었던 힘든 점, 극복했다면 해결 방법

음성 파일마다 형식, 음량, 무음 길이, 주변 소음이 달라 STT 모델에 바로 입력하기 어렵다는 점이 힘들었다. 이를 해결하기 위해 입력 형식을 통일하고 무음 제거, 노이즈 감소, 음량 정규화를 수행하는 전처리 과정을 구현했다. 또한 일반적인 문자 오류율만으로는 실제 파크골프 서비스에서 모델이 잘 동작하는지 판단하기 어려웠다. 그래서 타수 숫자와 주요 음성 명령의 인식 정확도를 별도로 계산하는 평가 기준을 만들었다. 다만 실제 경상도 방언 데이터로 학습을 실행하고 결과를 비교하는 단계는 아직 남아 있다.

## 내가 잘한 것과 더 잘할 수 있었는데 아쉬웠던 점

모델 조사에 머무르지 않고 STT/TTS API, 오디오 전처리, 데이터 준비, 학습 및 평가 코드까지 전체 흐름을 구체적으로 구현한 점은 잘했다고 생각한다. 특히 동일 화자와 대화 세션이 서로 다른 데이터셋에 섞이지 않도록 데이터 누수를 방지하고, 실제 서비스 명령을 기준으로 평가 지표를 설계한 점이 좋았다. 아쉬운 점은 학습 환경과 코드는 준비했지만 실제 데이터를 이용한 LoRA 및 DoRA 학습 결과를 아직 확인하지 못했다는 것이다.
