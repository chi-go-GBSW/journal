## 일주일 동안 내가 만들어 낸 것

지난 일지에서 발견한 [STT 전처리 이슈 #30](https://github.com/chi-go-GBSW/chi-go/issues/30)의 원인을 분석하고 VAD의 낮은 음량 처리 방식을 수정했다. 기존에는 FLEURS 한국어 음성 100개 중 42개를 VAD가 검출하지 못했지만, 수정 후 같은 100개 모두 전처리를 통과했다. 동일한 평가 방식으로 다시 계산한 결과, 수정 후 원본 음성은 CER 8.09%, WER 18.59%였고 전체 전처리를 적용한 음성은 CER 7.30%, WER 17.92%였다. 단계별 비교에서는 음량 정규화만 추가했을 때 정확도가 떨어질 수 있다는 점도 확인했다. 이 수치는 일반 한국어 읽기 음성에 대한 결과로, 실제 골프 명령이나 현장 소음에서의 성능은 추가 확인이 필요하다.

오늘은 SGLang Omni에 Whisper large-v3-turbo 모델을 올려 음성 인식 테스트를 진행했다. 기존 STT API에서 별도 모델 서버로 전사 요청을 보내는 연결 방식도 검토하고 코드를 작성했다. 모델을 안정적으로 서빙하고 전체 API 흐름을 검증하는 작업은 계속 진행 중이다.

## 일주일 동안 겪었던 힘든 점, 극복했다면 해결 방법

SGLang Omni를 실행하고 Whisper 모델을 테스트하는 과정에서 CUDA 드라이버 버전 오류와 SGLang이 요구하는 Python 버전의 불일치가 발생했다. 모델이나 전사 코드의 문제와 실행 환경의 문제를 구분해야 해서 시간이 걸렸다. 현재는 각각의 버전 조건을 확인하며 실행 환경을 맞추고 있으며, 오류를 모두 해결한 뒤 같은 음성으로 서빙 테스트를 다시 진행할 계획이다.

## 내가 잘한 것과 더 잘할 수 있었는데 아쉬웠던 점

전처리 문제를 추측으로 넘기지 않고 동일한 음성 100개로 수정 전후의 실패율과 인식 정확도를 다시 측정한 점은 잘했다고 생각한다. 새로운 서빙 방식도 직접 시도하면서 필요한 환경 조건을 확인했다. 다만 지난 2주 동안 일본 축제 등 일정으로 바빠 개발에 쓸 시간이 부족했고, 그만큼 모델 서빙 작업의 진도가 더뎠다. 다음부터는 바쁜 일정이 있더라도 미리 작업 시간을 나누어 꾸준히 진행해야겠다.
